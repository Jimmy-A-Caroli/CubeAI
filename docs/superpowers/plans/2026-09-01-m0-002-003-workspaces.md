# M0-002 and M0-003 Workspace Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Establish the smallest reproducible Python CubeLab and React/TypeScript workspaces without implementing product behavior or the later integrated slice.

**Architecture:** The backend exposes only a framework-free `cubeai.lab` package skeleton with one small value object; it deliberately contains no API endpoint, persistence, or external adapter. The frontend is a single Vite React page whose presentation component owns the visible status state and does not fetch data or define client infrastructure. The two workspaces have separate manifests, locks, source trees, and tests; no task edits shared documentation or the other workspace.

**Tech Stack:** Python `>=3.14,<3.15`, uv 0.12.7, PEP 621, Hatchling, pytest; Node `>=24,<25`, npm 11.19.1, React 19.2, TypeScript 5.9 strict, Vite 8.2, Vitest 4.1, React Testing Library.

**Spec:** `docs/issues/INITIAL_BACKLOG.md` (M0-002 and M0-003), `docs/adr/0003-initial-toolchain-and-web-first-local-capable.md`, and the supplied 2026-09-01 work-package instructions.

## Global Constraints

- Implement exactly M0-002 or M0-003; do not begin M0-004, M0-005, M0-006, M0-010, M1, or later work.
- Use the accepted toolchain exactly: Python `>=3.14,<3.15`, uv 0.12.7, Hatchling 1.28, committed `uv.lock`; Node `>=24,<25`, npm 11.19.1, committed `package-lock.json`, React 19.2, TypeScript 5.9 strict, Vite 8.2, Vitest 4.1, and React Testing Library.
- Keep `cubeai.lab.domain` framework-, adapter-, persistence-, and transport-independent. Do not add FastAPI endpoints, SQL, external calls, Docker, or product-domain models.
- Keep the frontend web-first and local-capable through one browser codebase; do not add routing, API fetching, authentication, state management, PWA/service workers, browser persistence, sync, replication, a desktop wrapper, or a design-system package.
- Prefer the smallest conventional implementation. Every non-baseline dependency must be necessary, used, and justified. Do not add optional dependencies.
- Use TDD for production code: record a focused RED command and its expected missing-feature failure before implementation, then record a focused GREEN command.
- Each task must commit only its workspace files. Do not edit shared README, milestones, backlog, ADRs, root configuration, or the other workspace; the controller handles final documentation state after both reviews.
